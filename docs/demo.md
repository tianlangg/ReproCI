# Demo script (about 90 seconds after setup)

1. Open `/docs` and show the API. Submit three runs of the demo's bad SHA in
   quick succession. Show two `running` jobs and one `queued`, then the stored
   failed `tests/test_total.py::test_total` result.
2. Replay that exact node ID. Show the new attempt ID, parent link, identical
   SHA and image ID, and repeated assertion failure.
3. Start bisect with `HEAD~4` as good and `HEAD` as bad. Show the endpoint and
   candidate attempts, followed by `first_bad_found` at `HEAD~3`. Explain that
   the result is specific to this fixed image and test.
4. Show `reproci report` and the benchmark summary. Mention that the two-second
   test is synthetic scheduling work, not a claim that an individual test got
   faster.

Follow-up: run the synthetic flaky test ten times and inspect attempt IDs and
outcomes. For a public demo repository, show a signed GitHub push delivery and
redelivery with the same delivery ID. A recording and public delivery are
external presentation artifacts, not generated by the local codebase.
